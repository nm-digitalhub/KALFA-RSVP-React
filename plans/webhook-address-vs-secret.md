# הפרדת כתובת ה-webhook מהסוד שלה — תוכנית

תאריך: 2026-09-22 · דיווח הבעלים: *"אין לי אפשרות לדעת מה כתובת ה-webhook? למה
אי אפשר שתישמר? למה להציג רק פעם אחת??"*

## 1. למה המצב הנוכחי כפוי, ולא נבחר

**נמדד.** הטוקן יושב בתוך הנתיב:

```ts
// webhook-token.ts:57
export function webhookUrlFor(origin: string, token: string): string {
  return new URL(`/api/workflows/hook/${encodeURIComponent(token)}`, origin).href;
}
```

ולכן **הכתובת היא הסוד**. מכאן נובע "פעם אחת בלבד" — לא כהחלטת UX, אלא כתוצאה
הכרחית של התכנון. `findWorkflowForToken` מחפש **לפי ה-hash בלבד**; אין שום מזהה
אחר לכתובת להיאחז בו.

**שתי תוצאות, שתיהן רעות:**

1. **הבעלים לא יכול לדעת את הכתובת.** אם איבד אותה, "יצירת טוקן חדש" **מחליפה**
   אותה ושוברת מיד כל מערכת שקוראת אליה — שקט, ובצד השני.
2. **הסוד דולף ללוגים.** סוד בנתיב נרשם ב-access log של nginx, בפרוקסי,
   בהיסטוריית דפדפן וב-Referer — בכל קריאה. ההגנה "רק hash בתרשים" מגינה על
   הייצוא ומחמיצה את הצד השני לגמרי.

## 2. התכנון החדש

```
POST /api/workflows/hook/<endpointId>
     x-kalfa-webhook-secret: <secret>
```

| | מה | נשמר | מוצג |
|---|---|---|---|
| `endpointId` | מזהה ציבורי, **לא סוד** | בתרשים, גלוי | **תמיד** |
| secret | האישור | **רק sha256** (`tokenHash`) | **פעם אחת** |

**מה זה פותר:** הכתובת גלויה וניתנת להעתקה תמיד; רוטציית סוד **לא משנה את
הכתובת** ולא שוברת אינטגרציה; והסוד יוצא מה-URL ולכן מפסיק להירשם בלוגים.

## 3. תאימות לאחור — נמדד, ולכן אין צורך

`trigger.webhook`: **צומת אחד, בתהליך אחד, `is_active = false`.** אפס תהליכים
פעילים. `findWorkflowForToken` מחפש רק ב**חמושים**, כך שהכתובת הישנה כבר היום
אינה עונה לאיש.

לכן **אין מסלול נפילה לאחור**, וזו החלטה ולא השמטה: מסלול כזה היה משאיר את
הסוד-בנתיב חי, וזה בדיוק מה שהשינוי בא להסיר. הצומת הקיים ייחסם ב-`arm-check`
עד שייווצר לו `endpointId` — כשל גלוי, לא שקט.

## 4. מה משתנה

| קובץ | שינוי |
|---|---|
| `webhook-token.ts` | `generateWebhookEndpointId()`; `webhookUrlFor(origin, endpointId)` |
| `catalogue/schemas.ts` | `endpointId` בסכמה + uischema |
| `catalogue/types.ts` | `endpointId` ב-`NODE_REQUIRED_FIELDS` |
| `webhook-token-control.tsx` | יוצר את שניהם; כתובת **תמיד**, סוד **פעם אחת** |
| `api/workflows/hook/[endpoint]/route.ts` | הנתיב = מזהה; הסוד מהכותרת |
| `webhook-trigger.ts` | `findWorkflowForEndpoint(endpointId, secret)` |

**`tokenHash` נשאר בשמו** — הוא באמת ה-hash של הסוד, ושינוי שם היה גורר הגירה
של שדה בלי להוסיף ולו ביט של בהירות.

## 5. מה שנשמר בדיוק כפי שהוא

ארבע התכונות ש-`webhook-trigger.ts` מתעד, אף אחת לא נחלשת:

1. השוואה ב**זמן קבוע** — עכשיו על שני הערכים.
2. **רק תהליכים חמושים** נסרקים.
3. הריצה **בלי אירוע ובלי איש קשר** — סוד שדלף עדיין לא מגיע לנתונים.
4. **תקרת גודל** לפני פענוח.
5. **תשובה אחת** לכל כישלון (404) — אין אורקל לקיום.

## 6. אימות

* מזהה נכון + סוד שגוי → 404. מזהה שגוי + סוד נכון → 404. חסר כותרת → 404.
* הכתובת אינה מכילה את הסוד — נבדק על המחרוזת עצמה.
* `endpointId` חובה ב-arm-check.
* הזרקת תקלה על כל בדיקה חדשה.
* lint · tsc · כל הסוויטה · build.
* **טרם אומת בדפדפן.**
